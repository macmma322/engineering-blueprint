# New, adopt and resume

## New project

Write the project facts, user outcome, constraints, non-goals, stack, integration branch, test commands and release gates. Compare a simple baseline with alternatives before committing to consequential architecture. Create only the documents and dependencies that the accepted scope needs.

## Adopt an existing project

Read the existing instructions, source layout, build and test commands, Git status, deployment map and decision records. Preserve stronger local rules and dirty work. Build a conflict matrix before editing documentation. Change only scoped files and verify the loaded instructions and representative runtime behavior.

## Resume work

Check the actual branch, base revision, worktree owner, roadmap, handoff, tests and open review. Separate observed evidence from stale promises. Continue the highest-priority authorized item and record the exact next action before stopping.

## Closeout

Review the diff, run applicable checks, record limitations and rollback, then update the roadmap. Do not infer production release, migration success, permission enforcement or remote recoverability from a local build.
